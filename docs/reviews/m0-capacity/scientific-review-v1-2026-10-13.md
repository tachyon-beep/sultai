One piece of evidence drives several findings below, so I state it once. From `posthoc_P1_low_alpha` in the attempt-4 summary (A1 restores the intact loss exactly, so A1 = intact host loss):

| anchor | intact loss | B3 loss | B3 gain over intact |
|---|---|---|---|
| 3004 | 0.601 | 0.553 | 0.048 |
| 3005 | 0.620 | 0.571 | 0.049 |
| 3003 | 0.683 | 0.547 | 0.137 |
| 3002 | 0.707 | 0.565 | 0.142 |
| 3001 | 0.709 | 0.582 | 0.126 |
| 3000 | 0.765 | 0.558 | 0.207 |

Intact losses span 0.164 nats; the module's endpoints span 0.035 nats (0.547–0.582), and the gain is monotone in the host's starting loss. The same pattern holds on the width-4 bottleneck hosts (`bottleneck_known_answer.w4`, P5): no-op losses 0.632–0.718, P5 endpoints 0.581–0.606, gain again monotone in starting loss. A module that compresses six independently trained hosts onto a common floor is the signature of finishing or calibrating an unconverged, constant-learning-rate host, not of capacity the host lacks. The draft's own §1 names this risk; its arms do not yet separate it.

## Findings

1. **BLOCKER — §5/§6, no zero-parameter control.** Every "cheaper route" in the arm table costs gradient steps on parameters; none is the route a hostile reviewer tries first: (a) re-estimate every BatchNorm running mean/variance on the 2,000 conditioning examples under no gradient (0 parameters, one forward pass; the host's running stats were accumulated under augmentation and are stale for unaugmented dev input); (b) a single logit temperature fitted on the conditioning examples (1 parameter); (c) temperature plus class bias (11 parameters). Loss is the primary unit (STEERING §4 rule 1) and the host is trained at constant lr 0.05 with no cooldown, so it is almost certainly miscalibrated; temperature scaling alone commonly buys 0.02–0.08 nats on such a host with zero accuracy change. The table above is exactly what calibration produces. Fix: add arms R-bn (BN recalibration), R-temp (1 parameter) and R-cal (11) at ~1–2 s per anchor; define the published no-op for V1 as the better of {host, R-bn}; report D1 both raw and net of R-cal; and pre-register that a V1 "present" in nats accompanied by a dev-accuracy difference whose lower bound is ≤ 0 is labelled "calibration, not capacity".

2. **BLOCKER — §5 R-272 is a straw man, so V1 is close to unfalsifiable.** 272 scalar entries drawn at random from a 64×16×3×3 kernel cannot express a channel mixing; the module is a full 16×16 map plus bias on tanh(z) with a residual, i.e. a strictly richer function class at the same count. D1 = G(M-sq) − G(R-272) ≥ 0.02 will read "present" on almost any host, including a merely undertrained one, because R-272 cannot absorb what the module absorbs. The repository already holds the correct matched-count control and the decision record already names it: the **affine 272 module** u = z + (W z + b), fitted by the identical oracle (D21 "folding control"; v4 §3 says "no affine oracle is run", which M0 must reverse). A per-position affine ahead of a conv folds into that conv's 9,216 + 64 existing parameters (exactly in the interior; at the zero-padded border the bias fold is approximate), so under STEERING rule 3 it is zero new capacity by construction, and D1 against it isolates precisely what the tanh nonlinearity buys. Fix: primary D1 = G(M-sq) − G(M-aff). Keep R-272 as descriptive only, and if kept require ≥ 3 fixed-seed draws per anchor rather than one. A structured second re-tune (the 16×16 sub-block of centre taps of the first downstream conv plus its 16 output biases = 272) is a reasonable middle control. Also flag the rate grid: raw conv weights were trained at lr 0.05 with momentum 0.9; plain SGD at {0.3, 0.1, 0.03} was chosen for a module at N(0, 1e-3) init and may be off-scale for them. Require the selected rate per arm to be reported with an "edge of grid" flag, and widen the re-tune arms' grid to {1, 0.3, 0.1, 0.03, 0.01, 0.003} (selection-chosen, so no unfairness to M-sq).

3. **MAJOR — §5 T-more cannot detect undertraining as specified, and is not matched in data.** Five more epochs at constant lr 0.05 / momentum 0.9 / batch 32 leaves the host at the same lr-set noise floor; the standard "is it undertrained" test is a decayed finish. Add T-cool: 5 epochs with lr decayed linearly or by cosine to 0 (also ~20 s per anchor). If T-cool alone buys 0.05–0.15 nats, which is typical for this regime, the module's 0.05–0.21 is largely finishing. Separately, T-more sees the 40,000 training partition and never the 2,000 conditioning examples that every module arm fits on, so "G(T-more) > G(M-sq) ⇒ undertrained" is sound in one direction only. The direct test of the confound is cheap and missing: **fit M-sq on the T-cool host**. If G(M-sq | T-cool) ≈ G(M-sq | host), the module is not harvesting undertraining; if it collapses, it is. One extra oracle case per anchor (~125 s). Make the second of these co-primary with D1 or at least a declared secondary with a bound.

4. **MAJOR — §4 data-regime confound untested.** All module and re-tune arms fit on 2,000 examples the host never saw; the frontier, T-more and S-static never see them. A module acting as a 272-parameter fine-tune on fresh data can show a gain that no 40,000-example route can match, and the N_eq and static-contrast readings would then be data artefacts. Fix: add M-sq-seen, the identical oracle fitted on 2,000 examples drawn (fixed seed) from the host's own training partition, with selection on a further 3,000 seen examples and the same dev endpoint. If G(M-sq-seen) ≈ G(M-sq) the fresh-data explanation is excluded. ~125 s per anchor.

5. **MAJOR — §5 S-static is not apples-to-apples.** host + M-sq = 40,000 host examples + a post-hoc fit on 2,000 extra examples with best-of-18 selection; S-static = 40,000 examples, no post-hoc fit. The static contrast therefore confounds "design-in versus insertion" with "2,000 extra examples plus selection". Fix: after S-static training, run the same oracle on the static host's module (host frozen) and compare S-static + refit against host + M-sq; report the un-refit contrast beside it. Two further specification gaps: (a) the static module's init is unstated (W = 0, b = 0 keeps the host's init identical to its anchor; say so); (b) the module parameters W (ndim 2) fall under weight decay 5e-4 in the recipe while the inserted module has none; state it. Also note the pairing is by data stream, not by host: once the graph differs the two trainings diverge from step one, so "paired on the seed" gives correlated, not matched, hosts, and the per-anchor SD of the static contrast will be of order the host's own seed-to-seed SD (≈ 0.06 nats from the table above), not the within-host paired SE. M_s = 0.02 against that noise with n = 6 or 16 is underpowered; say so or raise n for that reading.

6. **MAJOR — §7 V0 plateau rule has the wrong sign for a difference of two fitted arms.** In Gate 3 an unconverged oracle biased against "present"; here D1 = G(M-sq) − G(control) and D2 = G(cut, refit) − G(M-small), so an unconverged *control* biases **toward** "present" / "helps". A pooled 75 % certification fraction does not protect against this. Fix: "present" requires the control arm (M-aff or R-272) plateau-certified on ≥ 75 % of anchors and reports per-anchor certification of both arms; "re-tuning equivalent" requires M-sq certified. Exclude R-all from the plateau denominator (a 284,634-parameter fit on 2,000 examples is early-stopped by selection, not plateaued). Also: with 1 of 24 fits certified at 800 steps, the 800-versus-3,200 comparator may still leave the study indeterminate by construction; allow the pilot to extend the schedule axis (raise only, as Gate 3 allowed the anchor count) rather than forbidding it in §9.

7. **MAJOR — §3/§4/§6 V2 compute asymmetry; the Liu et al. control is incomplete.** M-wide→8 receives inherited weights plus 800 refit steps at one rate and one seed; M-small receives the full 18-candidate grid up to 3,200 steps. Liu et al. requires the scratch-trained small architecture to get at least the prune-and-fine-tune path's budget with a tuned schedule ("Scratch-B"). Both directions of D2 are confounded: "hurts" could be under-refit, "helps" could be the 2,128-parameter grid's extra search. Fix: give the refit the same grid as M-small (rate axis and schedule axis, selection-chosen; fits cost ~1 s per 200 steps so this is minutes); and add M-small-B, the built-small arm at the overgrow route's total optimiser steps (e.g. schedule {400, 1,600, 6,400}) or at least at the selected rate. Add the lottery-style arm (keep the surviving 8 units' *initial* weights, retrain) to separate inherited trained weights from lucky unit selection. Declare which pair defines D2 at matched compute.

8. **MAJOR — §8 ledger undercounts R-all and the pilot likely exceeds its ceiling.** The 125 s oracle kernel is for a fit through the frozen downstream with z cached. R-all trains every parameter from the images, so it needs the full forward and backward at batch 256 over (200 + 800 + 3,200) × 6 = 25,200 steps ≈ 6.45 M example passes per case; the host itself trains 400,000 passes in ~36 s launch-bound at batch 32, so a conservative 3–5× the module kernel gives 400–600 s per case, ≈ 3,000 s for six anchors instead of 750 s. Pilot total then ≈ 10,700 s against a 10,800 s ceiling with the added controls in findings 1–5 (~+1,500 s) not yet counted. The draft's own "if R-all exceeds 4× reduce to one seed" clause is likely to fire; pre-decide R-all at 1 seed × {200, 800} (800 steps is already 100 epochs of the conditioning set) and rebook. Also, running {200, 800, 3,200} as separate candidates spends 4,200 steps where a 3,200-step run with selection checkpoints at 200 and 800 is bitwise the same under a seed-derived data stream; that is 31 % of oracle time recoverable.

9. **MAJOR — §9 item 5 / §12 J7: confirmatory count and ceiling are inconsistent.** The §4 (v4) formula gives n* ≈ 38 at σ(D1) = 0.03 and ≈ 106 at 0.05, and the rule takes the larger of the D1 and D2 counts; for D2 at X₂ = 0.01 the half-width target is 0.005, so σ(D2) = 0.02 already gives n* ≈ 69. At ~900–1,300 s per confirmatory anchor (six oracle cases plus static, T-more, cuts) the 8 GPU-hour ceiling supports 22–32 anchors. The stop-before-freeze rule will almost certainly fire. Pre-specify now: size n on D1 only; report D2 with its achieved half-width; or raise X₂ to 0.02; and name the confirmatory arm set (R-aff and R-all are not in any D and could be dropped from confirmation) so the per-anchor cost is fixed before the pilot.

10. **MAJOR — §6 N_eq: relabel and bound it; the ratio to 272 should go.** The horizontal distance to the frontier is fine as a descriptive, and the 0.1 % delta is not itself the problem. The problems are: (a) four frontier points at 6 seeds each, with per-width SD ≈ 0.06 nats (the host's own seed spread), give a slope SE of roughly 0.03 nats per doubling, so N_eq's interval will span hundreds of thousands of parameters; (b) if L(host + M-sq) is below the F(1.5) mean, which the table above makes likely, N_eq is an extrapolation and must be reported as "beyond 613,018", not as a number; (c) the frontier is trained on 40,000 examples at 10 epochs while the module point has 42,000 and a selection step, so the horizontal comparison mixes data regime and recipe with capacity. Fix: report the frontier slope in nats per doubling with a seed-bootstrap interval, express the module gain as a fraction of one doubling with its interval, forbid extrapolation, drop "(N_eq − N)/272" from every label, and keep the "same-recipe frontier, 10 epochs" tag.

11. **MINOR — §1 premise overstated.** "Lowered development loss on every host it was tried on" is true, but every such host was impaired (P1 at α = 0.1) or bottlenecked (P5/P6); P8, the module on an unimpaired intact host, was never opened in attempt 4. The best proxy is B3 landing 0.02–0.21 nats below the intact loss from a P1-impaired start (table above). State that M-sq on the reference host is the first direct measurement and that its expected gain is 0.05–0.2 nats, correlated with the host's starting loss.

12. **MINOR — §3 truncation "as sliced" is a straw man for the strict reading.** Removing unit i removes V[:, i] · a_i; if a_i has a nonzero mean over conditioning positions (it will, post-tanh of a biased pre-activation), the cut shifts the output mean, which the bias d absorbs at zero cost. Fix: define "as sliced" with the exact mean fold d ← d + Σ_removed V[:, i] · mean(a_i) (applied to the random cut too), and report the un-folded slice beside it. Add a leave-one-unit-out loss ablation on the conditioning set (64 evaluations × 0.04 s) as the ceiling for the cheap ‖V‖·RMS criterion, which ignores redundancy between units.

13. **MINOR — §1/§3 the ExpandNets label is misapplied; the true ExpandNets control is free.** ExpandNets is *linear* over-parameterisation contracted *exactly* to the compact net; M-wide→8 is structured pruning plus fine-tune (the Liu et al. setting). The ExpandNets analogue at this site is W = W₁W₂ with W₁ 16×64 and W₂ 64×16 (2,048 + 16 bias during training), contracted exactly to the 272-parameter M-sq after fitting, compared against M-sq fitted directly. That is a clean "temporary capacity, fixed final size" test at zero extra retained parameters and ~125 s per anchor; add it as a V2 secondary or say explicitly that ExpandNets is not being tested.

14. **MINOR — §5 R-all with frozen BN statistics is handicapped.** Re-tuning 284,634 parameters on 2,000 examples with running statistics computed without those updates understates the re-tune ceiling, and the coarse {200, 800, 3,200} axis will skip its early-stopping optimum. Allow an R-all variant with BN recalibration after fitting (ties to finding 1) and select on a finer checkpoint grid (every 40 steps on selection). Also note that "optimiser parameter-steps" penalises R-all by 1,000× while its wall cost is 3–5×; book both.

15. **MINOR — §7 secondary readings are verdicts in disguise.** "Design-in beats insertion" (threshold M_s), "capacity on an undertrained host" (G(T-more) > G(M-sq)) and the re-tune-fraction label each binarise a statistic without stating which bound is used. Declare each as a secondary verdict with its bound type (one-sided 95 % anchor-bootstrap, as V1) and its own per-anchor pairing, or mark them explicitly as point-estimate descriptives. Also the sign convention of the static contrast in §6 (L(S-static) − L(host + M-sq)) is the opposite of its reading in §7 ("static better than inserted by more than M_s"); fix one.

16. **MINOR — §7 V0 lacks a known answer for the cut path.** V0 checks the fitter (P1, ρ = 0.8) and the printed count, but nothing certifies that slicing is correct. Add a unit test: an h = 64 module with 56 units' V columns set to zero exactly must, after the criterion cut to 8, reproduce its output within 1e-6 (bitwise after the mean fold), and a random cut must differ; plus a negative control that fails the test.

17. **MINOR — §6/§9 n = 6 statistics.** A one-sided 95 % percentile bootstrap of a median over six anchors is essentially the first or second order statistic. The draft correctly says "for the record only"; make sure §9 step 5 reads only the per-anchor SD and not any median, and consider for confirmation (n ≈ 16–32) reporting a sign-test or Wilcoxon exact bound beside the percentile bootstrap, whose coverage for a median at these n is discrete and known to under-cover.

18. **MINOR — §7 X = 0.02 nats is inherited from a repair question.** It was justified as "2–3 % of host loss, a worthwhile repair margin". For efficient capacity the relevant scale is what 272 parameters buy on the frontier (at ≈ 0.1 nats per doubling, 272/284,634 of a doubling ≈ 1e-4 nats), so any D1 > 0 is already "efficient" and X is a detectability floor against a per-example paired SE of ≈ 0.004 nats. Say that, so the margin is not later read as a capacity-efficiency threshold.

19. **SUGGESTION — §5 make the 20-epoch F(1.0) mandatory, with cooldown.** It is the cheapest from-scratch answer to "is the 10-epoch host just unfinished" (6 × ~80 s), and it is the compute-matched frontier reference STEERING rule 2 asks for far more than the 10-epoch sweep is.

20. **SUGGESTION — §5 Q1 on the 0.5 host.** If the frontier 0.5 hosts (seeds 6000–6005) double as Q1 anchors, say so in §11 and note that this makes them development anchors that cannot be reused as the M2 starved-host confirmatory set.

## Verdict

**ACCEPT WITH CONDITIONS.** The instrument, data seal, pairing, booking and verdict scaffolding carried from Gate 3 are sound, the parameter counts check, and the study asks the right question in the right units. But as drafted V1 can read "present" on a host that merely needs calibrating or finishing: the attempt-4 receipts already show the module compressing six hosts whose losses span 0.164 nats onto a 0.035-nat floor with gain monotone in starting loss, and no arm in §5 separates that from new capacity. Four conditions block the freeze and are arm changes, not margin choices: (1) zero-parameter controls (BN recalibration, temperature, temperature + class bias) with an accuracy co-read of V1; (2) the foldable affine-272 module as the primary matched-count control in place of random conv entries; (3) a decayed-finish T-cool arm and M-sq fitted on the T-cool host, plus the seen-data M-sq fit; (4) plateau certification required on the control arm for any "present"/"helps" reading. The remaining MAJORs (S-static refit, V2 refit grid and Scratch-B, the R-all ledger and the confirmatory count versus ceiling) should be dispositioned before John fixes J1–J7, because two of them change the per-anchor cost the sizing rule depends on. With those in, the draft is a preregistration I would sign.
