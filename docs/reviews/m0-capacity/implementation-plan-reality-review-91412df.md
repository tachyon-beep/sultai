## 2. Plan defects, ranked

1. **HIGH — The shared `Supervisor` cannot launch M0 children as planned.** `Supervisor.run` hard-codes `-m sultai_screen.screen` and the Gate 3 flag set `--output/--data-root/--seed/--width[/--training-root/--magnitudes]` (`pilot.py:163-184`); `Job` (`:50-58`) has no field for `--lineage`, `--scale` or widths; Gate 3 `main()` refuses any seed outside 3000–3005 (`screen.py:442-443`). Task 15 adds only `ceiling`/`per_card`; Task 17 then calls `Supervisor(root, data, ceiling=M0_PILOT_SECONDS, per_card=1)` to run `m0.worker` actions with frontier seeds 6000+ and `--lineage`. As written, every M0 child would be a Gate 3 worker that exits with a parser error. Fix: an additive `module: str = "sultai_screen.screen"` (or command-prefix) kwarg on `Supervisor` and an additive `extra: tuple[str, ...] = ()` field on `Job`, defaults reproducing today's command bytewise, pinned by a test that compares the Gate 3 command list.
2. **HIGH — Task 6 would break an existing test.** "Gate 3 `oracle()` … passes `checkpoints=()`": the fake in `tests/test_screen.py:822` accepts only `seed, rate, steps, minibatch`. Any explicit new keyword in `fit.py:283` raises `TypeError` under `patch("sultai_screen.fit.fit_sgd", …)`. Correction: `oracle` must not touch its `fit_sgd` call; the new keywords are defaults only.
3. **MEDIUM — Task 15 test assertion is arithmetically false.** `project_confirmatory(32, 1010, 1500)` = 33,820 s (within 43,200, correct); `with_static` = 32×1,120 + 1,500 = **37,340 s, which is within 43,200** (spec §8 itself says "leaves about a 1.16× margin"). S-static's exclusion under 12 h is **policy** (§10, J3/J7), not projection. Correction: the test asserts both projections are within 43,200 and that `with_static` is evaluated against `50_400` by rule (e.g. carries `ceiling_seconds: 50_400` / `requires_14h: True`), not "not within 43,200".
4. **MEDIUM — `optimizer_state(value: object, expected: dict[str, Tensor]) -> dict[str, Json]` cannot validate a real `SGD.state_dict()`.** CPU probe: a fresh optimiser's `state_dict()` is `{"state": {}, "param_groups": [ {weight_decay, lr, momentum, dampening, nesterov, maximize, foreach, differentiable, fused, params:[indices]} , …]}`; after one step `state` has 30 int-keyed `{"momentum_buffer": Tensor}` entries. So "exactly the keys of `optimizer.state_dict()` from a fresh matching host" rejects every saved state (fresh `state` is empty), `expected: dict[str, Tensor]` does not describe the structure, and the return type `dict[str, Json]` cannot carry tensors. Fix: define the saved format in the plan, e.g. a flat `{parameter_name: momentum_buffer}` `dict[str, Tensor]` validated against `host.state_dict()` shapes/dtypes (reusing the `checkpoint_state` pattern, `host.py:184-194`), with `param_groups` rebuilt from the recipe; bitwise resume then needs the buffer for all 30 parameters restored before the first resumed step.
5. **MEDIUM — Import isolation (Task 12) is unachievable with the dependencies the plan names.** `environment_identity` and `provenance` live in `screen.py` (`:88-116`), whose module imports `alignment` (`:19`) and `former_bridge` (`:46`); `pilot.py:45` imports `screen`. Task 16 says "follow `screen.worker` for the receipt envelope" and receipts need `physical_gpu`/environment fields that only `screen.provenance` produces today; Task 1's `source_identity` "follows `screen.source_identity`". If `m0.worker` or `m0.instrument` imports anything from `sultai_screen.screen` or `sultai_screen.pilot`, the Task 12 subprocess test fails at Task 16. The plan must state that `m0` reimplements (or `screen.py` relocates to an import-clean module) `environment_identity`, `provenance` and the envelope; `m0.pilot` importing `pilot.Supervisor` is the supervisor process and is acceptable under the spec's "workers' import path".
6. **MEDIUM — Task 4 / Task 11 signature mismatch.** `train_epochs(host: Host, …)` but `train_static` trains a `StaticHost(nn.Module)` that is not a `Host`, and the loop takes gradients over `tuple(host.parameters())` (`host.py:164-165`), which for a wrapper would need to include `w`, `b`. Under mypy strict this does not type-check and the gradient set is wrong unless `train_epochs` takes `nn.Module` (or a Protocol) and derives the gradient parameter list from the optimiser's groups. `state_hash(host: Host)` per epoch (`:174`) has the same typing issue.
7. **LOW — §2 item with no task:** "a training check that reads the width tuple, not only the bottleneck width". `screen._training` compares only `payload["width"]` (`screen.py:133`). Task 16's `train` payload adds `widths`, but no task or test names the M0 load-time check that compares `payload["widths"]` to the requested tuple before `load_host`.
8. **LOW — Review Focus 1 needs a defined "frozen" predicate.** Task 9's "raises `PilotHold` if the host is already frozen" has no source predicate: `freeze()` keeps no handle (`host.py:110`), `assert_frozen` checks mode/grad/hash (`:113-117`). Specify the detection (e.g. any `BatchNorm2d` with a registered `_bn_guard` pre-hook, or `not any(p.requires_grad)`), and note the guard only fires on a forward while in train mode, so the Task 4/9 tests must run a forward to observe the raise.
9. **LOW — Line citation:** `pilot.py:515` → `514` (claim 1e). `linear_cooldown` is unspecified for `step ≥ stop_step` (never reached by `COOLED_20`/`TCOOL` ranges, but the function is public). `check_policy.py:120` also treats `from_json`/`from_dict` as boundaries — add to Global Constraints.
10. **LOW — "the six Gate 3 tests" are not enumerated** (claim 9b lists eight candidates). Gate B cannot verify "untouched" without the list; name them in Task 12 Step 4 and Task 19.
