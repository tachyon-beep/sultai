Six questions remain where I would have to guess and a wrong guess changes the result, ranked:

1. How are the cheap-gradient arms B1/B2 (and A4/A5) specified, and what does B3's "1x schedule" mean in steps?
   The primary verdict V1 is H = median(B3 gain - B2 gain) against X = 0.02 nats. B2 is undefined on every axis that moves it by more than X: full-batch gradient over the 2,000 conditioning examples vs minibatch (size unstated); fixed learning rate (which?) vs a rate chosen on the selection set; momentum; "matched cost" in Table B is matched to nothing (Table A matches the supervised ridge's example passes; Table B has no supervised arm). One full-batch step and four minibatch-32 steps differ by roughly 60x in example passes, and the ledger line "cheap arms < 1 s" does not disambiguate. If B2's lr is selection-chosen it becomes a small oracle and H shrinks. B3's "schedule {1x, 4x}" has no base step count anywhere (the source design has none either), and its "3 seeds" need a definition of what a seed varies when the module is zero-initialised (minibatch order, presumably). Section 9 lets the pilot change the oracle grid but not the verdict logic, so the base definition of "SGD k steps" has to be in the document before freeze. This is the one place the whole headroom number is a free parameter.

2. Is P5's V0 criterion (oracle gain <= twin floor + 0.01 on >= 90% of anchors) meant as absolute, or relative to the matched hosts' P6/P8 oracle gain?
   The draft's own rationale for P8 is that a 272-parameter module can improve a weak intact downstream (the source design's Bansal/stitching argument). The same mechanism applies after the bottleneck: the data-processing argument says the module cannot recover information the bottleneck destroyed, not that it cannot improve the downstream's use of what remains. So in the outcome the screen hopes for (P8 headroom present), P5 probably also gains, V0 fails, the run is `instrument_failure`, and V1 is never read. The source design gave P5 a different ground truth: "site-sufficiency ceiling ~ host", a fresh wider downstream trained 20 epochs on frozen site features (Appendix A, labelling protocol), and labelled a case repairable only when its oracle gain beat the intact-host oracle gain by 0.05. The draft dropped the ceiling model and kept only the oracle. Plan impact: a relative criterion needs P8/P6 oracle gains as the reference (already computed); a ceiling model is a new ledger line and new code; the pilot is forbidden from changing verdict logic, so this must be settled before freeze.

3. Does any fitted arm other than A3 use the affine template, in particular A1 and B3?
   The draft's primary module is u = z + alpha(W tanh(z) + b), affine retained per D21 as a folding control. A1 "exact inverse, closed form" is necessarily affine (W = T^-1 - I); no W tanh(z) reproduces a 10x rescale of post-ReLU z, so under the tanh template A6 and A2 cannot reach A1 and the V0 line "A1 restores intact loss" is a check on the impairment code, not on the instrument. Narrow question: is V0's A1 check intended that way, and does D21's folding control extend to the oracle B3 (an affine B3 alongside the tanh B3)? If yes, the dominant ledger line (B3, 3,072-3,456 fits) doubles and V1 needs to say which template's H is primary.

4. What does the no-op twin vary?
   With the host frozen, every BatchNorm in eval mode and deterministic algorithms on, "a no-op twin on a resampled evaluation order" yields a bitwise or ~1e-7 difference: it is a determinism check, not a noise floor. Consequences as written: V0's "A1 restores intact loss within the twin noise floor" becomes a float-rounding test (z/0.1*0.1 != z at ~1 ulp through the downstream); P5's "<= floor + 0.01" collapses to absolute 0.01; B3's "plateau certified" (agreement within the twin floor, in the source design) is unachievable. The intended floor is presumably branch-to-branch within an anchor, or a bootstrap over evaluation subsamples; those give different numbers and different pass/fail for V0. The choice decides whether V0 is passable at all.

5. Which existing former is A7, and is V2 intended to be a foregone conclusion?
   Three generators exist (modes coarse, paired, paired_probes in /home/john/sultai/src/sultai/formation.py; a fourth 97x4 variant in formation_controls.py). The Gate 2 certificate reports paired and paired_probes; the draft says "the existing synthetic former" singular. Rebuilding it is decidable (run_formation() is deterministic from FIXED seeds; no weights file is needed). The real question is scientific: FrozenGenerator.form only returns materialize(4 coefficients), i.e. the span of public_templates() (identity, cyclic shift, alternating shift, alternating bias). P1's inverse is diagonal on 4 of 16 channels, P2's is Haar-random, P3's bias direction is arbitrary; none lies in that span, so V2 reads "does not transfer" by construction and does not test section 1's stated secondary aim. Does John want V2 as stated, or a refit of the meta-regression on real pairs (which section 6 forbids: "no refit")? Affects whether former_bridge.py is worth building beyond a stub.

6. What is P3's fixed bias-shift norm (and, less so, the scale convention for P1/P2 relative to z)?
   The source design says "c drawn per channel at a fixed norm" and gives no value; the draft repeats it. Post-ReLU z has a BN-set scale (order 0.5), so the norm determines whether A6 clears the 0.05-nat V0 gate or is trivial. Section 9 lets the pilot change counts, spawn point, oracle grid and replay rule, but not impairment parameters, so this cannot be calibrated in the pilot without a protocol change.

Decidable, stated for the record rather than asked: B4 retrieval's "nearest" metric is undefined because the telemetry tiers were dropped; I would use the aligned per-channel mean/covariance vector of z on the fixed unlabelled batch, leave-one-anchor-out, and treat it as the diagnostic it is declared to be.
