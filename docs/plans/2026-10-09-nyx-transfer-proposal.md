## Already settled: correction confirmation

The reviewed `2026-10-09-correction-protocol.md` fixes the current synthetic
host, four-template action family, oracle telemetry, seeds, splits, controls,
trajectory metrics and fail/stop meanings. The correction command needs one
CPU process and the standard library, no GPU or external dataset. The existing
120-second per-check ceiling applies; runtime and RAM estimates will be
replaced by measured development validation before handover.

Confirmation will execute on Nyx only after merged-source verification. It
does not satisfy HTTYE's beyond-template transfer or population safety gates.
If the controls show no learned advantage, publish that negative and stop the
current approach; more replicas are not a remedy for a failed hypothesis.

## Recommended next decision: headroom-only transfer screen

The smallest useful new experiment is a frozen-host screen before building a
new learned former or lifecycle integration. Use independently trained tiny
MLPs (8 inputs,32 nonlinear hidden units,16 outputs) on procedural nonlinear
regression. A dense teacher function generates task labels, not planted repair
coefficients. Fit eight development hosts on tanh-teacher tasks; freeze a
confirmation set of eight new sine-teacher task/host lineages. All checkpoints
and branches of one lineage stay together. Conditioning, selection, future
training and final audit samples have separate identity/provenance.

At the output site, ordinary observed task labels, host predictions and paired
output features are permitted. Teacher weights/hidden states and audit labels
are unavailable to the former. This is supervised paired telemetry containing
first-order information, explicitly not gradient-free formation.

Compare no-op, existing four-template learned former, analytic four-template,
unrestricted nonlinear272 ridge, affine272, and one/four-step SGD. Freeze equal
label access/candidate budgets; charge fitting and selection. This tests whether
a new host/interface has useful repair headroom and whether the existing
former transfers; it does not establish unrestricted learned formation.

Normalize targets using training-only statistics. Proposed screen criterion:
at least10% relative AND .01 normalized-MSE absolute improvement over no-op,
with every lineage reported. The absolute margin represents1% of normalized
target variance; the relative condition avoids trivial fractions on hard cases.
No lineage may degrade by more than .01 normalized MSE against its relevant
comparator in this finite screen. These are proposed engineering margins for
John, not calibrated safety limits and not chosen from confirmation outcomes.
Retain abstentions, failures, outliers and strongest-control comparisons.

Estimated resources, not measured: one CPU process, no GPU,1–5 minutes,2GiB.
Recommend a5-minute total ceiling if this option is selected, with no automatic
extension. Before launch, a separate preregistration must specify training
updates/batches, exact task construction, numeric seeds, sample sizes, source
and data hashes, and verify the estimate on development-only fixtures. This
proposal is not an executable burn command yet.

## Alternatives and tradeoffs

1. A staged learned-transfer study adds a frozen learned diagonal preconditioner
   that emits all272 weights from paired residual/feature moments (offline272
   coordinate scales). Use32 training+8 development tanh-teacher lineages,
   then8 unseen tanh and8 unseen sine lineages, reporting families separately.
   Compare empirical diagonal, ridge, SGD, retrieval and shuffled controls.
   Proposed formation criterion:5% lower mean loss than the strongest declared
   cheap baseline in each confirmation family, with unrestricted ridge retained
   as headroom reference. Only preregistered headroom success unlocks lifecycle.
   Proposed post-removal criterion:10% AND .01 improvement over no-growth,
   final-architecture and matched static arms over the first16 post-deletion
   updates AND final fixed horizon; .01 per-lineage degradation screen. These
   margins require John's decision. Unmeasured estimate:5–15 minutes,4GiB,
   one CPU process/no GPU; recommended total ceiling15 minutes. This requires
   new generator/host code and is a separate scoped implementation.
2. A small already-local real supervised dataset and tiny MLP gives stronger
   practical relevance, with observed labels and declared task-loss gradients.
   It needs a named dataset, license/provenance, independent host/task splits
   and classification-specific margins. Unmeasured estimate:10–30 minutes,
   4GiB, one CPU process/no GPU. No download/install assumed.

All estimates assume an existing numerical training stack on Nyx and are not
benchmarks. Parent must check installed tools, available memory and streaming
load. No timing estimate grants a resource budget. Choose the headroom-only
screen or the larger staged study together with domain, telemetry, margins
and ceiling as one owner decision, after reading correction outcomes.

## Explicit stops

Stop on invalid provenance, missing evidence, nonfinite state, exceeded budget,
insufficient headroom, or a preregistered negative. Preserve partial records and
faults; never turn an interrupted run into valid no-op labels. Do not change
thresholds, seeds, comparators or datasets after confirmation. Restart is an
explicit new attempt with linked provenance; no automatic budget reset.

Independent scientific reviewer supplied these alternatives and estimates
without executing experiments. Approval of the HTTYE route does not supply
the missing domain/resource/margin choices. A complete certificate may record
STOP / NOT READY while every observation and review is still delivered.
